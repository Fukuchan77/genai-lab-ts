## Purpose

生成 AI アプリ開発を基礎から 1 段ずつ積み上げる**入門ハンズオン・ラボ**。単一の Next.js アプリで、
Level 1（LLM 呼び出し・ストリーミング・構造化出力）から Level 2 の入口（ツール呼び出しと承認）までを
扱う。卒業先は `from-genai-to-agentic-ai`（4 フェーズ・19 モジュール）で、本ラボはその前段に位置する（D1）。

各段は「読む → 動かす → 改造する → テストで合格を確かめる」の単位で完結し、**API キーなしで
全テストが決定論的に通る**ことを前提とする。

## Users & Value

| User / persona | Need | Value delivered |
|----------------|------|-----------------|
| 生成 AI アプリ開発の入門者 | 小さく読める単位で、手を動かしながら基礎を学びたい | 1 段 = 1 概念。解説・実装・合格テストが対になっていて、到達をテストで判定できる |
| API キーを持たない学習者 | 課金や鍵の準備なしで同じ結果を再現したい | モックモデルと SSE モックで、全テストがネットワークなしで通る |
| 卒業を目指す学習者 | 次に何を学べばよいかを知りたい | 停止理由の語彙や API の書き方を卒業先と揃え、段 8 で対応モジュールへリンクする |
| ラボの保守者（人間とコーディングエージェント） | プレリリース版を使いつつ壊れた教材を出したくない | 単一ゲート（`mise run verify`）と、原則違反でテストかゲートが落ちる仕組み |

## Core Capabilities

段の順序そのものがプロダクトの骨格になる（段番号 = spec 番号）。

- **段 1 開発環境とゲート** — 以降のすべての段が依存する、決定論的で空振りしない検証入口
- **段 2〜3 LLM 呼び出しとストリーミング UI** — `generateText` / `streamText` と `useChat` による最小の対話
- **段 4 構造化出力** — `Output.object({ schema })` と Zod で LLM 出力を型付きデータにする
- **段 5 ツールと承認** — 停止条件 3 種と `toolApproval` を備えたエージェント（`createGuardedAgent`）
- **段 6 プロバイダ抽象化** — `AI_PROVIDER` / `AI_MODEL` を allowlist 内で切り替える
- **段 7 テストと簡易評価** — モック LLM と SSE モックによる決定論的テスト、ルールベース採点
- **段 8 安全性と卒業** — 入力上限・レート制限・プロンプトインジェクションの基本と、卒業先への橋渡し

## Product Principles

- **小さく読める**: 1 段は 1 つの概念に絞る。説明しきれない範囲は段を分けるか卒業先へ回す。
- **合格はテストで判定する**: 解説の合格条件ごとに対応するテストのパスを示す。テストに結びつかない
  説明は書かない。
- **再現性が品質の一部**: 「動く」に加えて「キーなしで同じ手順・同じ結果」を満たして完成とする。
- **安全策を最初に身につける**: 止まらないエージェント、読まれずに通る承認、秘密情報の漏えいを
  入門段階で防ぐ書き方を教える。
- **卒業先と同じ書き方を教える**: 非推奨 API（`generateObject` / `streamObject`）は使わず、
  停止理由の語彙も揃える。
- **複製せずリンクする**: 兄弟リポジトリの本文やコードは写さない。

## Out of Scope

以下は実装せず、`from-genai-to-agentic-ai` の該当モジュールへリンクする（憲章 原則 1）。

- RAG
- ワークフローパターン、マルチエージェント
- MCP
- 長時間実行ハーネス
- 本格的な Agent Evals（段 7 のルールベース採点までに留める）

段の追加・削除・範囲変更は、spec 000 の改訂を先に行う。
